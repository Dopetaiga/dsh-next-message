# DSH 建议插件设置向导

帮助用户完成安装或配置，不要求用户懂 YAML 或模型 ID。本 skill 不是运行插件；只操作选定目标中的 `dsh-next-message` 与 `next-message` 配置。

## 先看现状，再问缺失项

- 取值顺序：本轮用户意图 > 当前已有配置 > 首次默认。“保持”保留现有值，不表示恢复默认。只换模型就只换模型，不重装或重置其他参数。
- 用户指定的目标优先；自动发现可用 DSH 启动器、实际版本、`DSH_HOME` 和目标 profile，不假定路径或将 Desktop 与 Web 混用。共享 home 不代表共享插件安装、激活或配置。
- 先看当前实际工具列表；仅当 `plugin_manager` 在列表中时才按其实际 schema 调用，不能从源码或文档推断它可用。
- 查目标插件清单和生效配置。已安装优先读该版本的本地 manifest、bundle patch、`host.mjs` 的 `Config` 与 README；高级字段按这些来源查询，不复制另一版本的参数表。
- 只提取版本、相关配置和已有模型名称/非敏感 ID，不打印全量配置或进程命令行，不读取、复述、复制凭据或全量 `.npmrc`。安装公开 npm 包不以 npm 登录为前提，不执行维护者的发布登录流程。
- 目标不唯一才让用户选；可枚举项用可用的结构化提问工具，无工具则编号文本。每轮最多问 1–3 个相关缺失项，不机械走问卷，不重复已答内容。

没有 DSH，就说明依赖并引导官方安装；本 skill 不负责安装整个宿主。没有可用模型，就引导用户在宿主模型设置中安全配置，完成后重新检测，不在对话中索要密钥。

## 按意图继续

**首次设置：**检测目标和兼容包；未指定偏好时沿用会话模型、跳过前两轮、最近两组上下文。用户已说“按默认安装”就直接采用，不逐项问。想单独选模型时列实际已有模型供选择，用友好名称，必要时附 ID 消歧。

**修改现有：**简述当前相关值，只问所需依赖。例如“只换建议模型”就列可用模型及当前选择；其他值保持。关闭自动建议无需卸载。

**新增或更换目标：**重新检测目标；意图不明才问新增还是今后主要使用新目标。可复用非敏感偏好，但须核对目标模型；不搬会话或凭据、不删除旧环境。

用户想自定义跳过轮数或上下文时，按本地 Config 验证；不要把快捷默认值当成唯一选择。模型名称唯一可解析就无需再问 ID。

## 需要安装时

1. 查询 `dsh-next-message` 的 npm 元数据，根据实际 `engines.dsh` 选择兼容**精确版本**；不支持就说明并停止，不升级宿主或放宽兼容声明。
2. 默认走官方 npm；国内可选宿主支持的 `https://registry.npmmirror.com`。源缺版本时说明并选择可用源，不改全局 registry。两源均不可用才考虑本仓库 Release 或用户已有 tgz，不猜下载 URL。
3. 在目标 DSH 内，有 `plugin_manager` 才按实际 schema 安装；没有则走下面的用户 UI 交接。外部 agent 才考虑官方 CLI：先确认目标 profile 空闲；需要退出应用时须有正常退出授权，无法确认则等待。

若正在目标 DSH 中且当前工具列表没有 `plugin_manager`，停止查找内部入口，请用户在官方“插件 → 添加插件”中填写已核实的 `dsh-next-message@<兼容精确版本>`、按需选择镜像，等待用户安装后继续配置。不修改 preset 或权限来获得工具，不解包 asar、探测认证或 RPC，也不从自身 shell 运行外部安装 CLI。

```text
dsh plugin --profile <实际profile> add dsh-next-message@<兼容精确版本> --registry=https://registry.npmmirror.com
dsh plugin --profile <实际profile> list --depth 0
```

当前向导不能让目标 DSH 退出自己。不强杀、不删锁、不改应用文件；交接时保留已答选择，恢复后继续未完成步骤。

安装、启用不等于配置完成。检查安装版本与激活状态，保留用户明确禁用的覆盖项；然后读当前设置，只问未明确的偏好，按默认安装可直接保留默认。优先加载包内向导并**继续本轮配置**，不要求重新发指令或重问已答选项。仅链接不等于执行授权。

## 最小修改配置

- 默认沿用会话模型；独立建议模型的 `provider` 和 `model` 必须成对且来自已有注册路由。切回会话模型时同时移除两项，并检查旧 `reasoningEffort` 是否仍适用；不改主模型或凭据。
- 已安装时优先使用宿主支持的官方配置入口；只改 `next-message`。确认 home/profile/启动覆盖的优先级和原生效配置；Loader 的 `config` 是整份替换，先合并用户变更，再更新该条目的完整配置，保留其他插件、字段、注释与 YAML 标签。
- 修改前记录文件哈希和待改的非敏感值；已有条目原地修改，不追加冲突条目。无法确定实际覆盖层时报告具体歧义，不猜写入位置。
- 用一句人话概括结果和修改范围；已授权则执行，无需例行重复确认。仅权限、缺失选择或安全重启条件确实阻塞时再问。

## 核验后交付

用安装清单、激活状态、配置差异及可用运行状态区分“未安装”“已安装未启用”“已启用”“配置已保存待重启”“已生效”；缺哪项证据就说明，不能只凭保存成功称已生效。确认主模型与其他设置不变；无法判断覆盖层或生效状态时报告具体缺失，不猜测。

仅配置时不额外重装；确需重启才走已授权的正常流程并保留用户草稿。未证实的步骤不称成功，不为验证发送模型消息。

未经明确要求，不发送测试消息、不执行 `/suggest` 或真实模型调用。交付简述已完成的目标、所选行为和未完成项；失败停在具体阻碍，不循环重装。
