# DSH 建议插件对话式配置向导

这是供 agent 使用的设置助手，不是运行建议功能的插件。仅修改用户选定 profile 的 `dsh-next-message` 安装或 `next-message` 配置；已安装且只需改模型或开关时直接配置，不重装。默认沿用当前会话模型，不替用户挑选新模型、注册凭据或升级 DSH。

## 对话方式

用户只需选择或回答，不需要懂 YAML、provider ID 或字段名。先执行下文内部检测，再进入首次设置、修改现有或新增/更换环境分支。意图和目标明确时不要再问；不明确时首问：“这次想做什么？①给检测到的 DSH 开启建议 ②调整已有建议 ③换环境或新增 Web/profile。”

取值优先级是用户本轮明确指定 ＞ 当前已有配置 ＞ 首次默认。推荐默认只用于尚未选择的新设置，不能覆盖已有值；用户明确要求“恢复默认”才重置对应项。

可枚举项优先使用当前环境提供的 `AskUserQuestion` 或结构化提问工具；无此工具则用编号文本，不能假称已调用工具。每轮只问 1–3 个相关问题，收到回答再走依赖分支。只有未发现的路径、自定义数量等不可枚举值用自由文本。记录已回答的选择，不重复询问；“按默认”“保持原样”即视为选择相应默认，不为填表逐项确认。推荐项标“推荐”。模型使用友好名称，仅同名消歧时附必要非敏感 ID，不要求用户手填 provider/model。

收齐选择后用人话说明结果和修改范围；用户已授权安装或配置就执行，不反复确认。仅当缺少写入权限或不能安全重启时询问那一项。普通路径不展开所有参数，用户选择高级后才问相应数值。

## 首次设置

按依赖顺序进行，已明确的偏好或唯一已选目标直接跳过。用户说“按默认安装到桌面”时，只需检测目标及包兼容，不再问模型、自动时机和上下文。

| 阶段 | 简短问法与选项 | 接续行为 |
| --- | --- | --- |
| 选择目标 | “给哪一处开建议？①检测到的桌面版（若为当前使用环境则推荐）②检测到的 Web/profile ③其他位置” | 只对未发现的位置追问启动路径或 profile，再重新检测 |
| 插件包与兼容 | 发现兼容本地包则不问；没有时先查本项目 Releases 或源码，无法取得兼容包才问用户可提供的位置 | 多个兼容版本仅列实际发现的候选；宿主版本不支持则说明支持范围并停止，不修改宿主 |
| 建议模型 | “建议由哪个模型生成？①沿用当前会话（推荐）②单独选一个已有模型” | 选独立后列实际检测的模型名称供选择，自动映射 provider+model，不注册新模型或复制凭据 |
| 自动时机 | “何时自动给建议？①跳过前两轮，第三轮起（推荐）②每个完整回合后③仅手动” | 分别设置自动且跳2、自动且跳0、关闭自动；`/suggest` 不受轮次门槛限制 |
| 上下文 | “参考多少内容？①精简默认：最近两组（推荐）②展开高级设置” | 默认头300/尾900码点、总48000字节；高级先问想调整组数、长文本还是总量，只追问该项 |

模型和自动时机可放在同轮的两个问题，不把路径、模型和全部数字一次交给用户。汇总示例：“将给选中的桌面版安装建议插件；沿用会话模型，第三轮结束起自动建议，参考最近两组。”随后按内部执行说明落配置并核验，不把 YAML 当作用户必须填写的表单。

自动时机的三个选项只是快捷选择。用户可直接说“跳过前5轮”，此时采用该非负整数，不再限制为0或2；主动展开高级时也允许设置自定义跳过轮数。

## 修改现有设置

先展示当前相关值，如：“当前沿用会话模型，第三轮起自动，参考两组。”用户未说明改哪项时问：“想改什么？①建议模型 ②自动时机 ③上下文或其他高级设置。”选择后只问其依赖，不重走首次安装。

用户说“只换建议模型”时，首问直接是：“改用哪个？①检测到的模型A（当前值，如适用）②检测到的模型B③沿用会话模型。”只列实际可用候选，不能把示例名称当成已注册模型。修改时标识当前选择，不一律推荐回退到会话模型；推荐须有用户偏好依据。用户已给出唯一可解析名称则不再问。保留其他设置；仅旧推理档位不受新模型支持时，再问“改为支持的最低档（推荐），还是另选支持档位？”自动时机复用首次快捷选项并接受自定义轮数；上下文先给“精简默认／组数／长文本与总量”，不要逐项审问所有参数。

汇总示例：“只把建议模型改为你选的轻量模型；自动规则和上下文保持现状，不重装，也不改主模型。”已有配置写入授权即可执行。关闭自动建议不卸载插件。

## 新增目标或更换环境

重新发现新安装路径、实际 home、profile、版本、插件和已有模型，不沿用旧路径假设。多个可能目标时问：“新的使用位置是哪一处？①已检测到的 Web/profile ②另一处桌面安装 ③其他位置。”只对未发现位置追问路径或启动方式。

意图未明确时问：“这是新增使用位置，还是更换主要环境？①新增目标，旧环境照用（推荐）②以后主要用新目标，旧环境保留。”替换仅指今后使用目标变化，不删除旧安装或配置，不自动搬会话和凭据。

新目标已有插件就走修改分支，没有则检查包兼容并安装。展示旧目标的非敏感偏好，再问：“新目标怎么设？①复用旧偏好（推荐）②精简默认③重新选择。”复用仍须核对新版本支持的字段及目标自身模型；模型缺失或同名不唯一时才追问目标模型。不能复制旧 profile 的包清单、全量 patch 或凭据。目标未初始化则按官方启动流程引导初始化，不伪造 profile 文件，完成后重新检测。版本不兼容就明确停在该目标，不放宽范围或升级宿主。

汇总示例：“给新的 Web profile 单独安装，复用两轮门槛和精简上下文；建议模型使用新目标已有选择，桌面环境保留。”按已授权范围写入，不隐含卸载旧目标。

## 执行前自动检测（agent 内部）

没有 DSH 时说明依赖尚未安装，引导用户按其选择的官方发行渠道安装，必要时核实官方安装文档；本技能不声称自动安装整个 DSH。没有可用模型时，引导用户去宿主模型设置安全完成配置，不在对话中索要凭据；用户说完成后重新检测，再接续原分支。

1. 从可用的 `dsh` 命令、已安装应用启动器或用户提供的位置确认官方 CLI、运行方式及 `dsh --version`。不要假设机器路径、操作系统或版本。Desktop 自带 CLI 也可管理插件；先读其 `plugin --help`。
2. 确认实际 `DSH_HOME` 和目标 profile。默认 home 通常是用户目录下 `.dsh`，但须核对启动器环境或配置；当前 shell 的 `DSH_HOME` 不一定等于 Desktop 的值。Desktop 通常用 `desktop`，Web 用其启动参数选中的 profile。共享 home 的会话和凭据不表示共享插件激活：不同 profile 的包、bundle 选择及 patch 分别管理。
3. 读取目标 profile 的安装清单、bundle 激活状态与相关 patch，必要时用 `dsh plugin --profile <profile> list --depth 0` 核对。只提取版本、路径、插件状态和非敏感模型 ID，不打印完整配置或进程命令行。不读取、复述或复制 API key、token 和凭据文件；provider/model ID 从已有模型配置中定向提取。
4. 以目标插件 `package.json` 中的 `name`、`version`、`engines.dsh`、`dsh.bundle.patch` 为准，读取 patch 和 `host.mjs` 的 `Config` 核对字段。未安装时可检查用户提供的本地 tgz 内 `package/package.json`、patch 和 Host 文件，或所提供源码目录的对应文件。没有本地插件文件时，先读取本项目实际发布源 `https://github.com/Dopetaiga/dsh-next-message` 的 manifest 和 Releases，选择与宿主兼容的 release tgz 下载；不让首次用户先找本地包。没有兼容 release 时可读取该仓库源码，按 manifest 用 `npm pack --ignore-scripts` 打包，再由官方 CLI 安装；缺少打包依赖或网络不可用时才询问用户能提供的插件文件位置。不猜其他远程仓库、npm 包地址或安装网址，不执行来源不明的 `npx`。宿主版本不匹配时说明限制，不扩大兼容范围或改宿主。

本文件可单独复制使用，无必需的相对文件或其他 skill 依赖。插件源码或 tgz 是安装的实际输入，不能用本文件代替；仅有此文件时仍需发现已安装插件或取得用户提供的插件文件。

## 高级字段映射（按需使用）

此表供 agent 将已回答的人话选择映射到配置，只有用户展开高级时解释相关项。未要求改变的值保留，不创建测试会话来猜配置。

| 需求 | 配置与约束 |
| --- | --- |
| 使用当前会话模型 | 同时省略 `provider`、`model`；从独立模型切回时同时移除两项，并检查原 `reasoningEffort` 是否仍适用 |
| 独立建议模型 | `provider`、`model` 必须成对，使用现有注册 ID；只影响建议，不修改主会话默认模型或 Agent 设置 |
| 推理与输出预算 | 可选 `reasoningEffort` 须受建议模型支持；省略时取已公布最低档，未公布则保留提供方默认；`maxOutputTokens` 默认 2048，是建议输出上限，并非必耗 |
| 自动建议 | `automatic` 默认 `true`；`automaticSkipTurns` 默认 2，第三个完整根回合结束起生成；0 从第一轮起，`/suggest` 不受门槛限制 |
| 上下文组数 | `contextExchanges` 默认 2，范围 1–100；每组为真实用户请求及已完成最终回复，执行中可以只有请求 |
| 长文本 | `contextHeadChars` 默认 300、`contextTailChars` 默认 900，均为 Unicode 码点，范围 0–100000，不能同时为 0 |
| 总输入预算 | `maxInputBytes` 默认 48000，正整数；超限先丢最旧组，再缩短剩余组字段 |

这些默认值适用于包含这些字段的插件版本，修改前仍以目标版本的 `Config` 和 bundle patch 为准。工具输出、中间过程和压缩摘要不进入建议摘录；不要为“改善上下文”改主提示词、会话日志或记忆。

先确认所选 profile 中 `next-message` 当前生效配置，考虑 bundle 默认、home/profile patch 和启动覆盖层。Loader 的 `config` 是整份替换：将用户要求合并进当前生效的完整配置，再仅更新目标 profile 中对应条目的 `config`。已有条目就原地修改，不追加冲突条目；缺失时添加一个 `id: next-message` 覆盖条目。用保留 YAML 标签、`!!js`、注释和其他字段的局部编辑方式，不能把整个配置文件重新格式化或转换成 JSON。无法可靠判断层优先级或定位条目时，先报告具体歧义。

条目格式如下，字段值从现场和用户意图确定，不把示意内容写入真实文件：

```yaml
- id: next-message
  config:
    # 此处放合并后的完整 next-message 配置
```

修改前记录文件哈希与将变化的非敏感字段，保留可恢复的旧值；不把整个用户配置或凭据复制到项目、报告或对话。保存后确认 diff 只涉及 `next-message`，主模型配置、其他插件及设置不变。若更高层覆盖了该配置，说明实际未生效的位置，不擅自改全局层。

## 需要安装或卸载时

只在用户要求安装、更新、卸载，或配置所需插件尚未安装且用户已要求完成设置时操作。先确认目标 profile 已初始化。桌面 profile 被运行锁占用时，查看是否有活跃任务；空闲且允许重启则从应用菜单正常退出，无法确认或有任务就等待用户安排。不得强杀、删锁文件、覆盖安装目录或替换 `app.asar`。已有会话与用户草稿保持原样。

采用发现的官方 CLI 和本地绝对 tgz 路径；当前已验证的官方管理语法为：

```text
dsh plugin --profile <profile> add <absolute-tgz-path> --ignore-scripts --config.auto-install-peers=false
dsh plugin --profile <profile> list --depth 0
dsh plugin --profile <profile> remove dsh-next-message
```

`add` 安装并选择该 profile 的 bundle；检查已有禁用覆盖，不覆盖用户明确关闭的设置。保留其他包和激活项。检查命令结果及实际安装版本；需要重启时重新打开原官方应用。失败时停止相关后续操作，保留简短诊断，不循环重装或切换来源。

## 核验与交付

用安装清单、目标配置与必要的只读运行状态核验版本、激活和配置生效。若本轮无需安装或重启，不额外关闭应用。未经明确要求，不发送主用户消息、不执行 `/suggest` 或其他真实模型测试，不采纳模型建议，不运行完整测试套件。

简短报告目标 profile、安装或仅配置的结果、自动门槛、上下文限制及建议模型选择；默认模型说明“沿用会话模型”。列出修改的文件、仍需重启或未能确认的事项，区分已保存和已生效。说明卸载可用同一官方 CLI 的 `plugin --profile <profile> remove dsh-next-message`，并保留会话、既有凭证和其他用户设置。
